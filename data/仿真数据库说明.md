# 仿真数据库说明

数据库文件：[sbc_simulation_20260808.db](./sbc_simulation_20260808.db)，字段依据：[data_format.xlsx](./data_format.xlsx) 的第一个 sheet。

Excel 第一 sheet 定义了 **18 个逻辑接入源**，原基础版本有 **25 张表 + 3 个视图**。多出来的表不是重复，而是按用途分为四类：**接入源主表（18张）**、**关联明细表（2张）**、**仿真元数据与故障编排表（5张）**。第九节提供安全增量脚本，执行后增加两张观测表，成为 **27 张表 + 3 个视图**；原表、视图和字段不删减。本文旧章节的基线数量不代表增量已应用到现有数据库。

## 三、拓扑明细与落地关联表（2张）

拓扑JSON本身完整保留；另设明细方便查询。候选落地表则是仿真增加的关联证据，不是Excel显式定义的独立接入源：

| 表名 | 来源 | 说明 |
|---|---|---|
| `topology_edge` | 星间规划拓扑 / 星间实时拓扑的"拓扑详情信息" | 将60×60邻接矩阵拆成规范化的有向连接明细（每行一条源星→目的星方向），便于SQL查询某颗星的邻居 |
| `keepalive_landing_candidate` | 保活时间统计 + 选站路由信息的仿真关联 | 保存每段最优两个可达候选（不是全部候选全集），含QV地址、优先级、逐跳路径、有效期与对应馈电窗口 |

候选表列：`candidate_id`（主键）、`source_satellite_id`（业务星）、
`landing_satellite_id`（落地星）、`gateway_id`（地面站）、`qv_address`（仿真QV地址）、
`landing_address`（轨道面和星位编码）、`priority`（星间跳数，越小越优）、
`is_selected`（是否选中）、`route_path_json`（包含源星和落地星的有序逐跳列表）、
`valid_start_bdt` / `valid_end_bdt`（左闭右开有效期）、
`ground_link_id`（本次过境馈电记录的外键）。
同一落地星可以同时看见不同地面站，因此候选唯一键包含地面站。

## 八、轨道驱动的星地馈电与无连接服务仿真

### 8.1 时间、轨道与地面站假设

仿真窗口仍为 **2026-08-08 00:00:00.000 BDT 至 2026-08-09 00:00:00.000 BDT**，
所有区间均为 `[start, end)`。BDT为北斗时，不是北京时间，也不标注UTC的`Z`。

这是可复现的简化仿真星历，不是真实卫星过境预报：

- 60星、6轨道面、每面10星；球形地球半径6371 km，圆轨道高度2000 km。
- 地球引力参数398600.4418 km³/s²，倾角暂取88°。
- 六个**升交点赤经**依次为0°、60°、120°、180°、240°、300°，即按360°均分。
  如果“均匀分布”指无方向轨道面按180°均分，需要另改这项假设。
- 每轨初始相位为0°、36°、…、324°，轨间无额外相位偏移。周期由圆轨道公式计算，约127分钟。
- 为避免假装掌握真实轨道历元，**定义仿真起点格林尼治转角为0**，
  再按7.2921150×10⁻⁵ rad/s旋转地球。这不是该日期真实GMST；不把BDT误当UTC换算。
- 地面站采用近似城市坐标，并非实测天线址：

| 站ID | 名称 | 纬度°N | 经度°E |
|---|---|---:|---:|
| TJS | 天津 | 39.05 | 115.98 |
| GZS | 广州 | 23.13 | 113.26 |
| CDS | 成都 | 29.56 | 106.55 |

地面站在球面上的高度取0，最低可建链仰角取10°。
轨道传播和站星几何计算由 [sbc_orbit.py](../scripts/sbc_orbit.py) 实现。
窗口边界经数值求根细化到毫秒，入站向上取整、出站向下取整，保守保证建链发生在可见范围内。
日界处只保留当天部分；`peak_bdt`和`peak_elevation_deg`也是裁剪后窗口内的最高点。
`orbit_number`是依据初始相位与周期计算的仿真圈号，不再是地面站分配的序号。

### 8.2 馈电和组网星不再固定

1. 每颗星到每个站分别计算过境窗口，每个窗口生成一条 `ground_link_topology`。
   实际起止等于规划起止；`正常/连通`只在该记录区间内有效，区间外**没有这条馈电链路**。
2. 60星都假定具备馈电能力。`is_networking_satellite=1`表示能力，
   不表示24小时始终是组网星；时刻上的组网星应从有效馈电区间查。
3. **测控跟踪计划（互斥 + 全网不断链）**：一个地面站同一时刻只跟踪一颗星，一颗星同一时刻只接入一个站，
   不抢占、不换手。调度由 [sbc_schedule.py](../scripts/sbc_schedule.py) 实现，**首要目标是保证任意时刻
   全网至少有一条活跃馈电链路**——由于星间全连接（除A0603重构期），只要有一颗星地面可见并落地，
   所有星都能跨星中继落地。几何上全天任意时刻至少一颗星可见，因此**全网永不同时断链**。
   867个原始过境被筛选为168条跟踪弧段（TJS 61 / GZS 53 / CDS 54），写入 `ground_link_topology`，
   每条带唯一 `tracking_arc_id`。致密化阶段让58颗星获得本星直接落地弧段，其余2颗照样全天跨星落地。
4. **黏性选路（弧段内不换手）**：选路只使用当时的有向实时拓扑及有效馈电窗口。
   一颗星一旦选中某个落地星，只要该落地弧段仍活跃且仍可达就**保持不变**；
   只有在完全没有可达馈电（服务空窗）之后才允许重新选择下一个落地星。
   因此一个落地弧段内不会反复切站。保留每段的最优候选，有几个存几个。
5. **重构期剔除孤立中继 + A0603测控优先**：12:00–15:00 A0603重构期间，A0603本星可落地但**星间链路全断、
   无法为他人中继**。调度器做两件事：(a)骨干链选择时避开用A0603的过境作该时段唯一覆盖，
   保证其余59星始终有非孤立中继星；(b)**A0603获得测控优先权**——它每个过境簇（一圈内三站同时可见算一簇）
   都优先分配最高仰角的弧段，保证它"凡有过境必落地"，落地间隔尽量压缩在两圈（约4.23小时）以内。
   因此连续性统计中，**唯一无服务的是A0603自己**，为8445.8秒（重构隔离 + 其轨道几何决定的不可见空窗），
   其余59颗星全天0秒无服务。注意：14:46–21:27之间A0603对三站仰角全程<10°（几何不可见），
   这段约6.7小时无法建链是轨道几何的客观结果，非调度能改变。
6. `station_selection_route.constellation_type`填`A星座`，
   `无连接`保留在卫星体制字段中，不再误作星座类型。

### 8.4 四项时长的口径

统计不再硬写60行全天数值，而是按**实际候选有效期与理论服务边界的交集**逐段记账，
每颗星的统计子段无重叠地覆盖完整24小时。理论采用规划拓扑和规划馈电，
实际采用实时拓扑和实际馈电；当前无故障且零切换损耗，所以二者计算结果相等。

| 字段 | 计算方式 |
|---|---|
| 本星理论时长 | 理论选中本星直接馈电的子段时长 |
| 跨星理论时长 | 本星不能直接馈电、但理论可通过其他星落地的子段时长 |
| 本星实际时长 | 实际选中本星直接馈电的子段时长 |
| 跨星实际时长 | 实际通过星间链路到其他落地星的子段时长 |
| 规划/实际不可用时长 | 对应没有可达馈电的子段时长，分别保存在两个补充列中 |
| 中断次数 | 理论有服务而实际无服务的非计划中断起点；正常规划空窗不算故障中断 |

本星与跨星时长**互斥**；同一颗星同时过境多个站只计一次。
所有时长用REAL秒保留毫秒精度。每日`本星 + 跨星 + 不可用 = 86400秒`。
`feeder_start_bdt/end_bdt`表示所选馈电链路本身的窗口，可能长于该统计子段；
没有服务时二者为NULL。不应直接把这些馈电窗口逐行相加，应该汇总四个时长列。

`v_keepalive_interruptions`展示所有实际服务空窗，包括正常重构和覆盖空窗，
与`interruption_count`的非计划故障口径不同。

```sql
WHERE valid_start_bdt <= '2026-08-08 12:30:00.000'

```

汇总每日四项服务时长：

```sql
SELECT satellite_id,
       ROUND(SUM(local_theoretical_duration_seconds), 3) AS local_theory_s,
       ROUND(SUM(cross_satellite_theoretical_duration_seconds), 3) AS cross_theory_s,
       ROUND(SUM(local_actual_duration_seconds), 3) AS local_actual_s,
       ROUND(SUM(cross_satellite_actual_duration_seconds), 3) AS cross_actual_s,
       ROUND(SUM(actual_unavailable_duration_seconds), 3) AS unavailable_s,
       SUM(interruption_count) AS unexpected_interruptions
FROM connectionless_continuity_statistics
GROUP BY satellite_id ORDER BY satellite_id;
```

## 九、新增落地表更新观测与星上路由表采样

本节为增量方案，不要求重建已有数据库，也不修改 `sbc_simulation_20260808_V0.9-N.db`。
以上基线统计属于历史版本；新表只记录观测，不附带故障编号、诊断结论、原因、编排元数据或拓扑名称。
本次不涉及 LAN/WAN。

### 9.1 落地表更新上注及直接落地星回执

表名：`landing_table_update_observation`。一次内容更新可有多条地面上注尝试记录
`uplink`；**直接落地卫星**收到某次上注后返回一条接收/扩散报告
`receipt_diffusion`。馈电未建立时仍会持续记录上注尝试，但没有回执行；
不伪造“失败回执”或失败原因。

| 字段 | 含义 |
|---|---|
| `observation_id` | 本地观测行主键 |
| `update_id` | 同次上注与回执共用标识；`LTU-{ground_link_id}-{当日毫秒数，至少8位}` |
| `attempt_no` | 同一内容版本的发送尝试序号，从1连续递增；回执沿用触发它的尝试序号 |
| `event_type` | `uplink` / `receipt_diffusion`；同一次尝试各类最多一行 |
| `observed_bdt` | 该行记录时间，BDT，毫秒精度 |
| `landing_satellite_id` | 本次上注目标及回执报告卫星，仅直接落地星 |
| `gateway_id` | 对应信关站 |
| `ground_link_id` | 外键关联星地链路 |
| `tracking_arc_id` | 外键关联同一星地链路的跟踪弧段标识 |
| `candidate_ids_json` | 本次上注时刻，该弧段内有效的既有候选记录ID列表，按ID升序 |

**更新的确定性定义**：每条规划馈电弧段开始时上注一次；弧段内，任一已有候选记录
`valid_start_bdt` / `valid_end_bdt` 边界导致有效候选集合变化时，再上注一个新版本。
同一时刻只产生一次更新，相邻相同集合不重复产生更新，弧段结束时不再上注。
这是一种“弧段启用 + 候选记录版本变更”仿真口径，不声称重现真实设备的全部协议更新。
即使没有候选记录，弧段开始仍产生初始化上注。失败弧段可能完全没有实际候选，
此时 `candidate_ids_json=[]`，通过 `ground_link_id` / `tracking_arc_id` 关联规划上注目标，
不凭空添加候选或把其他弧段的候选关联进来。该列表是发送版本的关联索引，不是全星座收件人名单。

每个内容版本首次上注后，若3秒内未收到回执，则每3秒重发一次。若馈电已正常建立，
某次发送后1秒记录回执并停止该版本后续重发；回执必须严格早于实际馈电结束、
下一内容版本、规划弧段结束和当天结束。若整段没有回执，则重发到弧段结束前，
结束时刻及之后不再发送。没有足够时间完成回执的极短弧段也可能只有上注记录。
因此“多次上注且缺少回执”只是一种观测现象，本身不是根因判断。
回执关联的是原发送版本；不把回执回填到上注时刻，也不证明所有间接卫星都已完成扩散。

### 9.2 星上逐星路由表半小时采样

表名：`onboard_routing_table_snapshot`。每天 **60颗卫星 × 48次 = 2880行**。

| 字段 | 含义 |
|---|---|
| `snapshot_id` | 本地采样行主键 |
| `satellite_id` | 被查询卫星，外键关联卫星基础信息 |
| `queried_bdt` | 实际采样时刻；卫星与该字段共同唯一 |
| `entries_json` | 本次查询返回的路由项列表；没有原因或诊断字段 |

非空表固定包含另外59颗卫星（按卫星ID排序），**不含源卫星自身**。
每项字段：`destination_satellite_id`、`reachable`、`hop_count`、
`next_hop_satellite_id`、`path`。可达时记录最少有向跳数、下一跳及完整路径；
等跳路径采用邻接卫星ID字典序 BFS 确定。不可达时明确记录
`reachable=false, hop_count=null, next_hop_satellite_id=null, path=[]`，不省略目的卫星。
整个返回表为空时记录 `entries_json=[]`；与“59项全部不可达”不同。

时间范围为 **2026-08-08 00:00:00.000 至 23:30:00.000 BDT**，只在整点与半点采样。
所有新字段使用现有数据库的无时区标记 BDT 字符串；不转换为 UTC、北京时间或接收端当地时间。
时间窗口为左闭右开。例如17:20发生的变化首次由17:30查询反映，
19:10恢复首次由19:30查询反映；不新增17:20/19:10的路由观测，不回填先前采样。

每次采样以当时规划有向边为约束，使用不晚于采样时刻的最新
`laser_link_event` 物理通断观测。某条边没有物理观测时才回退到当时
`realtime_topology` 对应的 `topology_edge`。这区分了实时拓扑中的转发可达状态与物理链路状态：
不能把转发表丢失直接变成激光断链。采样不引用 `simulation_metadata` 的故障/观测标记，
也不解析 `change_source` 或拓扑ID中的名称。若规划/实时拓扑存在空洞或重叠，增量操作直接回滚，
不凭空假设全连接。

当前场景在 A0306 的 `[18:00,20:00)` 四次查询返回空表；20:00恢复普通表。
其他卫星继续基于同一物理图计算最短跳路由，不因此整表清空。它们可能仍保留经过A0306的路由，
这表示控制表观测与实际转发效果可能不同，不证明这些包已转发成功。
物理通断事件保持到下一事件，未建模传播时延、路由收敛、拥塞、ECMP或真实逐设备协议状态。

### 9.4 查询与判断规则

- `landing_table_query` 通过 `update_id` 关联上注和收到即扩散记录，不读取查询截止时刻之后的响应。
  没有回执只说明截止时刻未观测到回执；这不是根因标签。直连星的回执不证明其他星或全网已收到。
- `route_table_query` 查询真正的星上路由采样，不再把地面选站路由当成星上转发表。
  传 `observation_bdt` 时返回该时刻之前最近的采样及 `sample_age_seconds`，禁止使用未来快照。
- E1“落地网络联通分支末端节点”按当前实际落地路由树判断，不按物理邻居数量判断：
  目标星必须有经下一跳到实际可用落地星的路由，且没有其他源星的实际落地路径经过目标星。
  例如 `A星-B星-落地星` 且没有其他星经 A 星落地时，A 星是末端节点。
  判断使用当前选中落地目标及 `observation_bdt` 之前最近一次星上路由表快照。
- 保活初筛时，单星中断横跨多个规划落地星归为长时间，只涉及一个落地星弧段归为单圈次；
  两颗以上卫星的完整中断起止完全一致即为一批。固定落地星按中断开始时刻的规划落地星判断。
- D4在中断前最后选中的实际落地路由树上统计分支；E2使用选中落地目标与最近路由快照判断有无实际路径。
  E6的邻居来自当时实时拓扑中的上、下、左、右星，1轨和6轨边界星只有三颗。
- E3以截止查询时刻的最新落地表内容版本为准，任一发送尝试收到回执即算响应。
  F5要求相关规划馈电弧段在整段保活中断期间均由正常实际弧段覆盖。
- 激光 as-of 判断同时检查双向链路最新事件和两端终端最近遥测，两端均锁定才算正常。
  F7若存在相关 PacketIn 则优先采用 PacketIn 并跳过激光；无 PacketIn 才使用激光证据。
- F8只检查星上路由表。H16由 `route_path_diagnosis` 选取中断前最后一条选中落地路线，
  再用同一最近路由快照逐跳检查目的条目、可达性和下一跳，并返回首个异常跳。
- H2没有延时遥测时按“否”处理；I3记录“邻居卫星扩散响应计数未获取”后进入J4。
  F6当前直接结论为“需根据抓包结果具体排查”，普通 `packet_log` 不作为LAN/WAN分接口证据。
- 保活入口 `keep_alive_query` 只查询保活记录及由保活生成的中断视图，不使用连续性表代替保活证据。
  `connectionless_continuity_query` 在用户确认中断后提供连续性和事件分组。
- 中断必须原始起止均一致才合并；包含、相交或查询窗口裁剪后的边界一致均不算同一事件。
  同组按开始时刻的规划邻居优先遍历，这只是取证顺序，不表示共同根因。
- PacketIn 按同一 `affected_link` 的 LINK_DOWN/UP 的 `occurred_bdt` 分别匹配中断和恢复，
  绝对时间差上限为 4.5 秒（包含边界），不使用地面接收时间。数据截断或缺失时不强行出判断。
- LAN/WAN 分接口收发本轮不模拟，普通报文日志不能代替该证据。
