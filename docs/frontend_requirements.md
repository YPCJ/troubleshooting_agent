# fault_assistant_AI 前端界面需求文档（确认版 v1.0）

## 1. 文档目的

本文档用于明确 `fault_assistant_AI` 项目的前端界面建设需求。当前阶段仅做需求澄清与范围定义，不进入详细设计与编码实现。文档将随着需求问答持续迭代，直至达到可实施状态。

## 2. 项目现状理解

基于当前项目结构，系统已有以下基础能力：

- 以 Python 为主的智能体/脚本型项目
- 已存在多个 `Apps`，如：
  - `fault_search`
  - `fault_diagnoses`
  - `document_write`
  - `log_transform`
- 已存在多个 `Skills`，通过 `SKILL.md` 进行描述和装载
- 已存在多种输出物：
  - Markdown 报告
  - PNG 图片
  - JSON / CSV 等中间文件

因此，前端不应只是一个“聊天框”，而应是一个围绕 **Agent/App 调度、Skills/Tools 管理、会话隔离、结果归档与查看** 的 B/S 控制台。

## 3. 建设目标

建设一个 B/S 架构的 Web 界面，使用户可以：

1. 选择不同的 `Apps（功能入口）` 发起任务
2. 查看、启停、配置和管理 `Skills`
3. 查看和管理可供 Agent 调用的 `Tools`
4. 为每一次 Agent 实例运行提供独立工作区（独立窗口或页签）
5. 在每个运行实例中独立保存：
   - 对话记录
   - 中间过程
   - 结果文件
   - 图片 / 报告等产物
6. 方便地回看、复用、导出历史运行结果

## 4. 目标用户

当前目标用户包括：

- 直接操作智能体系统的研发/测试人员
- 进行故障分析、图表生成、报告生成的业务使用者
- 需要检查 Skills、Tools 与运行过程的管理员/维护人员

已确认存在多角色区分，当前至少包括：

- 管理员用户
- 普通用户

其中：

- 管理员用户：可管理用户权限；对 Skills 和 Tools 具备新增、删除等管理能力
- 普通用户：可使用所有 Apps / Skills / Tools；可编辑 Skills 的 Markdown 文档；不具备 Skills/Tools 的增删权限

## 4.1 术语约定

为避免概念混用，本文档统一采用以下术语：

- **App**：面向用户的功能入口，例如 `fault_search`、`document_write`
- **Agent 实例**：用户启动某个 App 后，实际执行任务的智能体运行实体
- **Session**：某个 Agent 实例对应的一次完整会话记录，包含消息、工具调用、产物、状态等

关系说明：

- 用户在前端选择的是 **App**
- 系统实际启动的是 **Agent 实例**
- 前端 Tab 与历史记录承载的是 **Session**

## 5. 产品范围（当前草案）

### 5.1 本期建议纳入

#### A. 主工作台壳体页（唯一主页面）

- 登录后默认进入主工作台，而不是额外拆分首页
- 主工作台固定包含三块区域：
  - 左侧 Session 列表区
  - 左下功能导航区
  - 中间主内容区
- 左侧 Session 列表区用于：
  - 展示当前用户可见的 Session
  - 分组展示：运行中 / 最近会话 / 已归档（更早历史）
  - 打开已有 Session
  - 通过 `New` 创建新 Session
- 左下功能导航区用于切换主内容视图，至少包括：
  - 智能体 / 应用
  - Skills
  - Tools
  - 结果中心
  - 用户与权限（管理员）
  - 系统设置
- 中间主内容区根据当前选择切换不同视图

#### B. 新建 Session 视图 / App 选择与 Agent 实例启动

- 点击 `New` 后，不跳转独立首页，而是在主工作台中进入“新建 Session 视图”
- 在该视图中：
  - App 字段使用下拉可选框，并从现有 Apps 中选择
  - 展示每个 App 的名称、说明、输入要求、可调用 Skills/Tools
  - 支持选择 App 后启动一次新的 Agent 实例
  - 支持填写本次任务输入（文本、文件路径、参数）
  - 文件输入提供“上传文件”按钮与“路径输入”方式，且文件输入为非必填
  - 支持继续最近一次同类任务的参数模板（如后续实现）

#### C. 会话工作区（核心）

每次 Agent 实例运行对应一个独立会话页签或页面。已确认优先采用 **单页面内多 Tab** 方式，而不是浏览器多窗口。每个 Session 至少包含：

- 对话区：展示用户输入、agent 回复、工具调用过程
- 运行状态区：运行中 / 已完成 / 失败 / 已取消 / 已暂停
- 输入参数区：本次会话启动参数
- 产物区：图片、报告、日志、结构化结果文件
- 历史区：本会话完整交互记录
- 当用户切换到 Skills / Tools / 结果中心等管理视图时，当前 Session 上下文必须被保留
- 系统必须提供快速回到“当前 Session 视图”的入口，建议至少包含：
  - 左侧 Session 列表中高亮当前 Session
  - 主内容区顶部固定显示“返回当前 Session”按钮或当前 Session 面包屑
  - 从 Skills / Tools 视图一键返回最近活动 Session
  - 如果 Skills / Tools 配置被修改，返回 Session 时提示“能力配置已更新，是否刷新当前会话上下文”

#### D. Skills 管理

- 列表查看全部 Skills
- 查看 Skill 元数据与说明
- 查看 Skill 对应的 `SKILL.md`
- 查看 Skill 的输入/输出约定
- 查看 Skill 是否可用
- 按用户权限控制操作能力：
  - 管理员：可新增、删除、编辑、启停 Skill
  - 普通用户：可编辑 Skill 的 Markdown 文档内容；不可新增/删除 Skill
- Markdown 编辑需提供版本管理能力（版本历史、回滚）

#### E. Tools 管理

- 展示系统可调用 Tools 列表
- 展示每个 Tool 的用途、参数结构、可见性、使用限制
- 查看某次会话调用了哪些 Tools 以及调用结果
- 按用户权限控制操作能力：
  - 管理员：可新增、删除、配置 Tool
  - 普通用户：仅查看与使用，无管理权限

#### F. 运行记录与结果中心

- 按会话查看历史运行
- 按 App / 时间 / 状态检索
- 统一查看输出文件：
  - Markdown 报告
  - 图片
  - JSON
  - CSV
- 支持下载、预览、复制路径
- 与“当前 Session 视图”的职责区分：
  - 当前 Session 视图：按执行顺序实时展示消息流、技能/工具调用与输出
  - 运行记录与结果中心：面向历史归档与分析，提供分类检索与统计视角

#### G. 用户与权限管理

- 支持多用户登录使用
- 支持至少两类角色：
  - 管理员
  - 普通用户
- 支持按角色控制页面可见按钮与后端操作权限
- 支持用户、角色、权限的基础管理

#### H. 基础大模型接入与管理

- 首期支持两套基础模型通道接入：OpenAI API、Gemini API
- 架构上必须保留接入其他模型提供方的扩展能力（例如新增第三方模型通道时不改动上层业务流程）
- 支持模型选择与运行绑定：
  - 新建 Session 时可选择模型通道与模型名称
  - Session 创建后记录本次运行使用的模型配置
- 支持模型管理视图（管理员）：
  - 管理模型提供方、可用模型清单、默认模型
  - 控制哪些模型对普通用户可选
  - 配置并验证连接信息（如 Base URL、模型名）

### 5.2 当前建议暂不纳入首期

- 在线协同编辑
- 多租户
- 工作流编排设计器
- 远程节点调度 / 分布式执行面板

## 6. 关键需求拆解

### 6.1 主工作台壳体与区域职责

- 系统采用“单一主工作台壳体 + 多视图切换”模式
- 不再单独拆分首页与 Apps 独立页面
- 主工作台固定包含三块区域：
  - 左侧 Session 列表区
  - 左下功能导航区
  - 中间主内容区
- 区域职责：
  - 左侧 Session 列表区：展示可见 Session（运行中 / 最近会话 / 已归档更早历史）、打开已有 Session、创建新 Session、标识当前 Session
  - 左下功能导航区：切换智能体/应用、Skills、Tools、结果中心、用户与权限（管理员）、模型管理（管理员）、系统设置等视图
  - 中间主内容区：承载当前视图（Session 运行或管理视图）
- Session 分组口径（统一）：
  - 运行中：状态为 `running` / `queued` / `paused`（未最终结束）
  - 最近会话：已结束会话（`completed` / `failed` / `cancelled`）中，按更新时间倒序取最近 N 条
  - 已归档：其余更早历史会话

### 6.2 新建 Session 与 App 启动需求

- 点击 `New` 时进入“新建 Session 视图”，而非跳转到独立首页
- 系统能够自动发现或注册已有 Apps
- 在新建 Session 视图中展示 App 的名称、说明、输入要求、可调用 Skills/Tools
- 智能体 / 应用视图需独立展示当前可选 Apps，采用卡片/图标化布局，用户可一眼识别并点击进入新建 Session（自动带入 App）
- 启动新会话时必须先选择 App（下拉框单选）
- 每个 App 可以有不同输入表单
- 选择 App 后，系统创建对应 Agent 实例，并进入对应 Session
- 文件输入为可选项（非必填），支持上传按钮和路径输入两种方式

### 6.3 Session 运行与视图切换需求

- 一个浏览器中可同时存在多个 Session（单页面多 Tab 交互）
- 每个 Session 必须独立维护：
  - 消息记录
  - 运行状态
  - 产物列表
  - 上下文参数
- 切换 Session 或关闭 Session 不得污染其他 Session
- 关闭页签后历史仍可从记录中心找回

当用户切换到 Skills / Tools / 结果中心等非 Session 视图时：

- 不得销毁当前 Session 上下文
- 必须保留最近活动 Session 标识
- 必须支持一跳返回当前 Session

快速返回机制至少包括：

- 左侧列表高亮当前 Session
- 主内容区顶部固定“返回当前 Session”入口
- 最近活动 Session 快捷入口
- 左侧 Session 点击即回切
- 若 Skills / Tools 配置已变更，回切 Session 时提示“能力配置已更新，是否刷新当前会话上下文”

### 6.4 Skills 与 Tools 管理需求

Skills 视图要求：

- 展示 Skills 列表、描述、来源路径、状态、依赖资源
- 查看某个 Skill 被哪些 App / Session 使用过
- 权限化操作：
  - 管理员：新增、删除、编辑、启停
  - 普通用户：可编辑 Skill 目录下所有 Markdown 文档；不可增删 Skill
- Markdown 编辑必须提供版本管理能力：
  - 历史版本列表
  - 版本对比（至少文本差异）
  - 一键回滚

Tools 视图要求：

- 展示 Tool 名称、说明、参数 schema、调用记录、失败信息
- 权限化操作：
  - 管理员：新增、删除、配置
  - 普通用户：仅查看和使用

### 6.5 会话记录与结果产物需求

“当前 Session 视图”与“运行记录与结果中心”的边界：

- 当前 Session 视图：
  - 面向实时交互
  - 主体区域以问答内容为主
  - 右侧边栏展示技能/工具调用记录与输出结果（产物）
  - 整体仍按时间顺序流式刷新执行状态与新增内容
- 运行记录与结果中心：
  - 面向历史回看与治理
  - 提供分类检索、聚合统计、跨 Session 对比能力

交互记录要求：

- 保存完整问答记录、工具调用轨迹、时间戳、错误信息
- 支持按会话导出记录
- 多用户场景下必须标识会话归属
- 支持会话级统计字段（至少）：
  - 消息总数
  - Skills 调用次数
  - Tools 调用次数
  - 错误次数
  - 会话总耗时
  - 产物数量与类型分布

结果产物要求：

- 每个产物必须绑定来源 Session
- 支持图片、Markdown、JSON、CSV 的预览与下载
- 支持按类型筛选
- 支持从结果反查来源 Session
- Artifact 元数据字段至少包括：
  - created_by
  - mime_type
  - size
  - checksum

### 6.6 会话控制需求

首期必须支持：

- 启动
- 暂停
- 继续
- 取消
- 重跑

补充要求：

- 所有会话控制操作必须保留操作日志
- 暂停定义为硬暂停（立即中断执行）
- 重跑定义为从头重跑（从第一步重新执行）
- 重跑支持复用原始输入参数
- 暂停/继续/取消后状态需实时刷新

### 6.7 文件输入需求

输入方式必须同时支持：

- 直接填写服务器/工作目录路径
- 前端上传本地文件

补充要求：

- 上传文件与所属 Session 绑定
- 展示原始文件名、存储路径、上传时间、上传用户
- 单文件大小上限：30MB
- 支持文件类型：文档、图片、短视频
- 默认存储路径规范：`data/uploads/{user_id}/{session_id}/{YYYYMMDD}/`

### 6.8 用户权限、可见范围与认证需求

权限模型：

| 能力 | 管理员 | 普通用户 |
|---|---|---|
| 登录系统 | 是 | 是 |
| 使用 Apps | 是 | 是 |
| 使用 Skills | 是 | 是 |
| 使用 Tools | 是 | 是 |
| 编辑 Skill Markdown | 是 | 是 |
| 新增 Skill | 是 | 否 |
| 删除 Skill | 是 | 否 |
| 新增 Tool | 是 | 否 |
| 删除 Tool | 是 | 否 |
| 管理用户/权限 | 是 | 否 |

数据可见范围：

- 普通用户仅可查看自己的历史会话、交互记录、生成结果与上传文件
- 管理员可查看全部用户数据
- 所有列表页和详情页必须做后端权限校验，不能仅依赖前端隐藏按钮
- 管理员视角支持按用户筛选会话与结果

认证方式：

- 本地账号密码登录
- 支持管理员创建/禁用用户
- 支持用户修改自己的密码
- 密码不得明文存储

### 6.9 基础模型选择与管理需求（OpenAI / Gemini）

- 首期支持 OpenAI API 与 Gemini API 两套基础模型接入
- 架构需支持扩展接入其他模型提供方（通过模型通道适配层扩展，不影响 Session/工具/视图层）
- 新建 Session 视图支持模型选择：
  - 提供方（OpenAI / Gemini）选择
  - 模型名称选择（来自可用模型列表）
- 模型选择可配置策略：
  - 系统默认模型
  - 用户按 Session 覆盖
- 管理员可在模型管理视图中：
  - 配置模型提供方连接信息
  - 配置可用模型清单与默认模型
  - 配置普通用户可见可选模型范围
  - 执行连通性验证
- 会话记录中必须保存模型提供方与模型名称，便于审计和复现

## 7. 非功能需求

### 7.1 架构形态

- 采用 B/S 架构
- 用户通过浏览器访问
- 前后端分离或轻量一体化方案均可，但需便于后续扩展
- 必须支持多用户登录与权限校验
- 必须提供模型通道适配层，统一封装 OpenAI / Gemini（及后续新增模型提供方）的调用差异，对上层暴露一致接口（会话创建、消息调用、工具调用、流式输出、错误处理）

### 7.2 易用性

- 中文界面优先
- 结果查看路径清晰
- 对图片、Markdown 报告提供开箱即用的预览能力
- 权限不足时要有明确提示，不允许静默失败
- 可用性验收指标（首期）：
  - 主工作台首屏进入后可交互时间 ≤ 3 秒（常规网络环境）
  - Session 视图切换响应时间 ≤ 1 秒（非重载场景）
  - 从 Skills/Tools 视图回切当前 Session 操作路径 ≤ 1 次点击
- 权限不足提示需统一文案模板，至少包含：原因、建议操作、联系管理员入口

### 7.3 可维护性

- App / Skill / Tool 元信息尽量配置化
- 新增 App / Skill 后，前端最好无需大改即可接入
- Skill Markdown 版本管理需定义保留策略（例如按条数或按时间窗口保留历史版本）
- Skill / Tool / Model 配置变更必须记录变更日志（变更人、变更时间、变更前后摘要）

### 7.4 可追踪性

- 每次运行有唯一 ID
- 可追踪是谁、何时、使用哪个 App、调用了哪些技能和工具、生成了哪些结果
- 对涉及 Skills/Tools 管理操作的新增、删除、编辑行为保留审计日志

### 7.5 安全要求

- 所有权限判断必须以后端校验为准，前端隐藏按钮仅作为体验优化
- 账号密码必须安全存储（不可明文存储），并支持密码更新与账号禁用
- OpenAI / Gemini 连接凭据必须集中托管，不允许在前端明文暴露
- 文件上传需校验大小、类型与归属会话，拒绝非法格式与超限文件

### 7.6 性能与容量要求

- 单文件上传上限 30MB（首期硬限制）
- Session 列表、结果中心、调用记录列表必须支持分页与筛选
- 历史会话查询和结果检索在常规数据量下应保持可接受响应（默认筛选条件下 ≤ 2 秒）
- 模型切换、Skill/Tool 视图切换不得导致当前 Session 上下文丢失

### 7.7 可用性与恢复要求

- 会话控制（暂停/继续/取消/重跑）失败时必须给出明确失败原因与重试入口
- 硬暂停与取消操作必须具备状态一致性保障，避免界面状态与后端执行状态不一致
- 结果文件与会话记录需支持归档与恢复策略，避免误操作导致数据不可恢复
- 管理视图配置变更后，用户返回 Session 时必须提示是否刷新上下文，防止“配置已变更但会话无感知”

## 8. 页面与信息架构（修订版）

建议的信息架构如下：

1. 登录页
2. 主工作台壳体页

主工作台壳体页内包含以下主视图：

- 新建 Session 视图
- Session 运行视图
- 智能体 / 应用视图
- Skills 管理视图
